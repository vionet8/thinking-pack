# 参考モデルレポートツールの設計メモ: 解析モデルで落としてはいけないものと、その使い道（2026-10 会話の整理）

**grounding**: 本人（CAEの実務者）との会話を Claude が整理したもの。「本人の言葉」は quote、それ以外は
Claude の整理（paraphrase・要検証）。ツール本体は見ていない。重みの表や閾値は一般論のたたき台で、
現場の経験で直す前提。

## このメモを使う場面

- **使う条件**: 解析モデル（構造系のFEモデル）を読み取って、設定の要約・チェック・作成の手順化や自動化をする
  道具を作る・直すとき。例（これに限らない）: 参考モデルのレポート出力、納品前のモデルチェック、
  見積もりの根拠づくり、モデル作成のマニュアル化、メッシュ作成の自動化、新人へのモデル作成の教え方。
- **向かない場面**: 解析結果（応力・変位・周波数など）の評価や合否判定。ここで扱うのは「モデルの設定」で、
  結果の良し悪しではない。流体・電磁場など構造以外の解析は、項目を読み替える必要がある。

## 1. 目印の基準: 影響の大きさ × 気づきにくさ

全項目を同じ重さで並べたレポートは、どれも目に入らない。目印をつける基準は
**結果への影響の大きさ × 画面で見て気づきにくいか**（FMEAの影響度×検出度と同じ考え方）。
「部品が1個無い」はジオメトリを見れば分かるが、「単位系のずれ」「結合が1本切れている」は画面上では
何も変わらない。目印が必要なのは後者。

目印は「値」ではなく**差分**につける。標準との差、前回モデルとの差、目標値との差。
ベテランが参考モデルを開いて「ん？」と引っかかるのも、差分に反応しているから。

## 2. 落としてはいけない内容

### A. 結果に直結し、画面では気づけないもの（最優先）

| 項目 | なぜ危ないか |
|---|---|
| 単位系 | mm-t-s と mm-kg-ms の混在。密度やヤング率が桁違いでも計算は回る |
| 境界条件（拘束） | どの点のどの自由度を止めているか。拘束不足・過拘束はどちらも黙って結果を変える |
| 荷重・ロードケース | 大きさ、向き、参照座標系、時刻歴カーブ、ステップの順番 |
| 材料の割り当て | 物性値より「どの部品にどの材料が当たっているか」。塑性カーブ、ひずみ速度依存、破断条件 |
| 板厚・要素の定式化 | 板厚、オフセット、積分点数、要素タイプ、アワーグラス制御 |
| 結合 | スポット溶接・ボルト・接着・RBE。RBE2かRBE3かで剛性が変わる。ボルト軸力 |
| 接触 | 定義漏れは貫通、余計な定義は張り付き。摩擦係数、初期貫通 |
| 質量 | 総質量・重心が目標と合っているか。集中質量で代用している部品、非構造質量 |
| 座標系 | 荷重・材料方向・出力に使うローカル座標系 |
| ソルバー設定 | 解析タイプ、非線形オプション、終了時間、減衰、マススケーリング（陽解法では最小要素サイズでタイムステップが決まる）、出力要求（要求していない量は後から取れない） |

### B. 標準から外している箇所（参考モデルの価値は本当はここ）

参考モデルが参考になるのは、ベテランが意図的に標準から外した判断が埋まっているから。
モデルから「何をしたか」は読めても「なぜそうしたか」は読めないので、一番抜け落ちやすい。
例（これに限らない）: 局所的なメッシュの細分化、省略・簡略化・剛体化した部品、試験と合わせるために調整した
パラメータ（減衰、結合剛性など）、無効にしてある接触・結合、既知の不具合を避ける回避策。

「標準と違う箇所」を自動で拾い、そこに「理由」欄をつける。理由が空欄なら、それ自体が要確認のサイン。

### C. モデルの素性（どこまで信用してよいか）

元にしたCAD・部品のリビジョン、モデルのバージョン、試験相関の有無と範囲（範囲外は参考値）、
既知の制約、品質チェックの結果（未結合部品、自由端、重複した節点・要素、IDの衝突、要素品質）。

### D. 目印は要らないもの

部品名、色、グループ分け、要素数の合計など。落としてもすぐ気づくか、結果に効かないもの。

### 目印の段階（案）

- 🔴 要確認: Aでチェックに引っかかったもの
- 🟡 意図確認: Bの「標準と違う」箇所。理由が書かれていなければ確認する
- ⚪ 情報: 標準どおり。折りたたんでよい

## 3. 一番の軸は「用途」で、目印の基準は用途ごとに変わる

本人が考えている使い道は3段階。同じ項目でも、用途が違うと目印をつける理由が変わる。
例: 「部品Xが剛体化されている」は、見積もりでは客先への確認事項、マニュアルでは理由を書くべき判断ポイント、
納品チェックでは剛体のままかを照合する項目。

| 用途 | 知りたいこと | 目印をつけるもの | 重要度の基準 |
|---|---|---|---|
| ① 事前整合・見積もり | 何がどれだけあるか、何を客先と決めておくか | 数量、標準外の設定、意図が読めない設定 | 工数への影響 × 不確かさ |
| ② 作業フロー（マニュアル化） | 何をどの順で決めるか | 判断が要る箇所 | 判断が要るか、機械的にできるか |
| ③ 納品モデルのチェック | 参考モデルの設定どおりにできているか | 揃っているべきものの差分 | 結果への影響 × 気づきにくさ |

**① 事前整合・見積もり**: 出力を「規模（部品数、要素数、結合点数を種類ごと、ロードケース数、特殊なモデル化の有無）」と
「確認事項（標準外・意図不明の設定）」に分ける。解析上重要でも、標準どおりで明確なものは目印不要。
影響が小さくても意図不明なものは工数のぶれになるので目印をつける。

**② マニュアル化**: モデルは完成形のスナップショットなので、**作業の順番と理由は入っていない**。ツールが出せるのは
「決める必要がある項目」と参考モデルでの値まで。項目を依存関係の順（材料・板厚 → 結合 → 接触 → 境界条件・荷重 →
ソルバー設定 → 出力）に並べ、判断が要る箇所に「理由」欄を空けて人が埋める。判断ポイントは厚く、機械的な作業は薄く書く。

**③ 納品チェック**: 参考モデルとの差分を全部出すと、形状が違う以上ほぼ全部が差分になる。
「揃っているべきもの」（単位系、材料カード、要素の定式化、接触の設定、結合のモデル化方法、出力要求、ID範囲・命名規則）と
「変わってよいもの」（形状、部品構成、要素数、結合点数）を分け、前者の差分だけを出す。
差分が①で合意した変更なら問題なし、合意にない差分が🔴。

**3つは1本の流れにつなぐ**: 設定一覧の抽出は共通で1回だけ作る。①で詰めた合意事項を③のチェック基準にそのまま使う。
②に溜まった「理由」が、次の案件で①の確認事項を減らす。

## 4. 二番目の軸: 解析の種類ごとの重み（主に③で使う）

どの解析でも常に🔴なのは、単位系、材料の割り当て、未結合部品・自由端、出力要求の漏れ。
それ以外は解析の種類で効き方が変わる。表は1枚にして、項目は共通、重みを列で持つ（解析ごとに別リストにすると保守がつらい）。

◎ 必ず目印 ○ 確認 △ ほぼ効かない・通常は定義なし − 該当なし（一般論のたたき台）

| 項目 | 衝突 | NVH | 静強度 | 耐久 |
|---|---|---|---|---|
| 拘束 | ○ | ◎ フリーフリーか拘束ありか | ◎ 評価部位の近くで過拘束していないか | ◎ |
| 荷重 | ○ 初速・バリア条件 | ○ 加振点・方向 | ◎ | ◎ 単位荷重ケースと荷重履歴の組み合わせ |
| 材料 | ◎ 塑性・ひずみ速度・破断 | ○ 弾性定数と密度 | ○〜◎ 非線形なら塑性も | ◎ S-N曲線 |
| 板厚 | ◎ | ◎ 曲げ剛性は板厚の3乗に比例 | ◎ | ◎ |
| 結合 | ◎ 破断の設定 | ◎ 結合剛性がモードを決める | ○ | ◎ 溶接点が亀裂の起点 |
| 接触 | ◎ | △ | ○ 非線形のときだけ | △ |
| 質量・重心 | ◎ | ◎ | △ 慣性リリーフを使うなら○ | ○ |
| 局所メッシュ | ○ 座屈・折れの部位 | △ | ◎ 応力集中部 | ◎ 応力集中部 |
| 減衰 | △ | ◎ | − | △ |
| マススケーリング・時間刻み | ◎ | − | − | − |

解析の種類は、デッキから判定できるものは自動で（例: Nastranの SOL 101 線形静解析、SOL 103 固有値、
SOL 111 モード周波数応答）。耐久は静解析の結果を疲労ツールに渡すことが多く、ソルバー側で区別できないので手で選ぶ。

## 5. モデル作成の自動化（4ステップ）

1. **参考モデルから部品ごとの「作り方」を逆算する**: 要素タイプ、狙いの要素サイズ・最小サイズ、三角形要素の比率、
   板厚、中立面かオフセットか、材料、穴まわりの処理（ワッシャー要素、節点数）、Rの列数。
   ただし「どの形状を残し、どれを潰したか」はメッシュだけでは分からない（消した形状は残らない）。
2. **新しいCADの部品と参考モデルの部品を対応付ける**: 部品名・品番、外形寸法、板厚、材料、組み付け位置、形状の類似度で
   候補を出す。自信が高いものは自動、低いものだけ「この部品はどれですか？」と新部品と候補3つの画像を並べて人に選ばせる。
   「該当なし」も選べるようにし、その場合は新規部品として作り方を人が決める。回答は記録して次の候補出しに使う。
3. **作成順は依存関係から決める**（参考モデルには順番が入っていないので、学習よりルールで組む）: 形状修正・中立面 → メッシュ、
   節点を共有させる部品は基準側が先、結合は両側のメッシュの後、同じ段階では重要な部品を先（早くレビューに回せる）。
   依存関係のグラフにして並べればワークフローになる。
4. **メッシュを切るのは既存のメッシャーに任せる**: ANSAなら、Batch Mesh のセッションにメッシュパラメータと品質基準を持たせて
   部品を割り当てる。ツールの仕事は「どの部品をどのセッションに入れるか」とパラメータファイル作り。
   品質基準を満たせなかった部品は、人が直すリストとして出す。

2の結果で部品が「対応あり（自動）」「対応あり・要確認」「新規」に分かれ、それがそのまま①の見積もりの根拠になる。

## 6. 形状のルールは、参考モデルの真似ではなく物理から作る

真似で作ったルールは、対応する部品があるときしか使えない。物理から作ったルールは「該当なし」の新規部品にも当てはまる。
**守りたい物理量 → それを決める形状量 → 形状の扱い**の順で決める。

| 守りたいもの | 効く形状量 | ルールの例（閾値は未定） |
|---|---|---|
| 質量 | 体積（面積×板厚） | 穴を埋めても部品の質量変化が○%以内なら埋めてよい |
| 引張・圧縮の剛性 | 断面積 | 荷重経路の断面積を○%以上変える穴・切り欠きは残す |
| 曲げ・ねじりの剛性 | 断面二次モーメント | ビード・リブ・フランジは小さくても残す |
| 強度・耐久 | 応力集中（R、穴縁、切り欠き） | 評価部位のRは列数を確保し、穴にはワッシャー要素 |
| 衝突での変形の仕方 | 座屈の起点（ビード、穴、断面変化） | 小さくても起点になる形状は残す |

- 面積だけで判断すると、曲げに効くビードを潰してしまう（ビードは面積をほとんど変えないが、断面の高さを稼ぐ）。
  剛性は、引張なら面積、曲げなら断面二次モーメントと分ける。
- 何を守るかは解析の種類で変わる。同じ小穴でも、NVHなら埋めてよく、耐久なら評価部位では残し、衝突なら座屈の起点は残す。
  4の重みの表が「どのルールを効かせるか」の切り替えになる。
- **参考モデルのCADは、ルールの検証に使う**: 元CADにルールを当てて残す・潰すを判定 → 実際の参考モデルのメッシュと比べる →
  食い違いを見る。食い違いは「ルールが足りない（ベテランが物理的な理由で残した）」か「参考モデル側の癖」。
  前者は理由ごとルールに足す。こうするとルールは基本に忠実なまま、経験の分だけ育つ。
- 始め方: 最初は部品単位で当てる（役割と解析の種類から「この部品は穴径○mm以下を埋める、Rは○列」と決め、
  Batch Mesh のセッションに振り分ける）。穴やビードを1つずつ判断するのは次の段階。

## 7. 名前のルール

ツールが読める形にする。区切り文字と並び順を固定し、使える語は辞書で決める。
例（これに限らない）: `<部品識別>_<役割>_<板厚>_<材料>` → `BPLR-INR_FRAME_t1.6_SPC590`

- 「役割」（骨格部材、パネル、ブラケット、付属品など）は入れる価値が高い。物理ルールを当てるには
  「荷重経路上の部品か」が要るが、形状から自動判定するのは難しい。名前に役割があれば当てるルールを決められる。
- 効くところ: ①役割ごとの部品数を数えられる、対応付けで候補を絞れる（人に聞く回数が減る）、
  ③名前の板厚・材料と実際の設定を照合できる。
- 参考モデルの名前は客先のルールなので、自分たちの辞書へ読み替える対応表が別に要る。

## 8. 作る順番（おすすめ）

1. 設定一覧の抽出（全用途で共通）
2. ③納品チェック: 過去に問題になった納品モデルを流して、その問題を拾えるかで効果を確かめやすい
3. 部品ごとの作り方の逆算と、部品の対応付け: 自動実行がなくても「部品ごとの作り方指示書」として人が使える
4. 自動実行は最後: 対応付けが間違ったまま実行だけ自動化すると、間違ったモデルが速くできるだけ

全種類の解析を一度にやらず、一番よくやる解析の列を1本作り込み、目印が役に立ったかノイズだったかを見てから広げる。
