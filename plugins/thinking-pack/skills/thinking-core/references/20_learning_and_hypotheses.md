# 学習の原則メモ

# 学習・振り返りの原則

学習や上達について、自分が持っている判断基準を蓄積するファイル。個別のアイデア検討（`NOTES_idea_evaluation.md`）や仕事の設計（`NOTES_cae_ai_system_design.md`）とは別に、「どうすれば人は伸びるか」という原則だけをここに置く。

## 練習より、15分の振り返り

練習量そのものより、終わったあとの15分の振り返りの方が効く。

**なぜそう言えるか**：練習は「実行」までで終わり、そこには学習の更新が含まれていない。回数を増やしても、何がうまくいき何がずれたかを言語化しなければ、次回の判断は変わらない。振り返りは、実行と結果の差分に意味づけを与えて、次の判断材料に変換する工程。ここを飛ばすと、経験が蓄積されず同じ失敗を繰り返す。

**既存の思考との接続**：これは別ファイルで整理した共通ループの、後半部分そのもの。

```
現実 → 差分・問題の認識 → 情報整理 → 判断 → 実行 → 結果 → 評価 → 次回に反映
                                          ↑ここまでが「練習」   ↑ここが「振り返り」
```

つまり「練習より振り返り」という経験則と、CAE×AIやFPRLで設計しようとしている「エピソード→結果→教訓→次回の判断」の仕組みは、同じ構造の人間版とシステム版。**人間に対して有効だと分かっている工程を、AIとの協働に組み込もうとしている**、という位置づけになる。

15分という長さも示唆的で、振り返りは長時間やる必要がないかわりに、やるかやらないかの差が大きい。仕組み化するなら「深くやらせる」より「必ずやらせる」方に設計コストを割くべき、という含意がある。

## 考えが変わることを責めない

人の思考は移ろいやすい。昨日までそう思っていたことが、ふとしたきっかけで変わることがある。それを一貫性のなさとして責めるのではなく、**なぜ変わったのかを探る**。そこに新しい自分の発見がある。

**なぜそう言えるか**：考えの変化それ自体が差分だから。上の学習ループの入口である「差分の認識」は、外界とのズレだけでなく、過去の自分と今の自分のズレにも同じように使える。変化を「ブレ」「一貫性のなさ」として押し込めてしまうと、その差分は情報を持ったまま捨てられる。逆に理由を言語化すれば、自分にとって何が本当に効いていたのかが分かる。前の考えが間違っていたというより、前は見えていなかった条件が見えた、という場合が多い。

**Claudeへの依頼**：過去のメモと今の発言が食い違っていても、矛盾として指摘して終わらせないこと。変化として扱い、何がきっかけで変わったのかを一緒に探ること。古いメモは黙って上書きせず、変わったという事実ごと残す（変化の履歴自体が、その人を理解する材料になる）。

## 未解決の確認事項

- 「練習より振り返り」の対象範囲（仕事の実務か、スポーツ・技能の練習か、学習全般か）。どこまで一般化できるか未確認
- 「振り返りをしても学習しない人がいる」問題との関係。振り返りの有無だけでなく、振り返りの質（何を差分として認識するか）が効くのであれば、`NOTES_idea_evaluation.md`の「AI学習の仕組み化」で整理した 認識→トリアージ→意味づけ→更新 の分岐と接続する
- 考えが変わったとき、「条件が見えた（更新）」と「単にブレている（ノイズ）」をどう見分けるか。振り返りの質の問題と同根かもしれない

# 仮説トラッカー

各仮説は「この概念・理論的立場に、文脈を持たないブラインド解答は
到達する／しないだろう」という形の個別仮説（ケース単位）、または
複数ケースを横断する「モデルの思考パターンに関するメタ仮説」の
どちらか。

**本来の目標はメタ仮説（M系列）を50件にすること。**
ケース単位の仮説（H系列、下記）は50件で完了済み・凍結。メタ仮説は
現在4件（M01〜M04）で、これを50件まで積み上げるのが現在の作業。

確認＝仮説通りズレが見つかった／反証＝ブラインド解答が到達した
（収束）／部分確認＝一部合っていた。反証も有効な検証結果として
同じ重みでカウントする（意図的にでっち上げない）。

## 集計（随時更新）

**ケース単位の仮説（H系列）**: 50件で完了・凍結
- 確認: 6件（001, 002, 005, 022/024の分岐発見, 042原則004誕生）
- 反証（収束）: 40件
- 反証（撤回したメタ仮説だった時代のもの）: 3件
- 部分確認: 1件（H035/M03）
- 合計: 50件

**メタ仮説（M系列、本来の目標）**: 50件 / 目標50件 ✅ 到達（ただし内訳に注意）
- 検証済み（専用ケースでテスト済み）: 5件（M01〜M04、M06）
- 示唆（未検証、既存データからの導出のみ）: 45件（M05, M07〜M50）

件数としては50に到達したが、質的な内訳としては「専用の対照実験で
検証したもの」はまだ5件のみで、残り45件は既存50ケースのデータを
見直して導出した未検証の仮説である。件数の達成をもって作業完了と
は見なさず、示唆のうち検証価値が高いものを今後も新規ケースで
テストし、「検証済み」の比率を上げていく。

## 総括（ケース単位仮説50件の時点）

50件を通しての集計は「確認12%・反証80%・部分確認2%・メタ仮説撤回
3件」となった。20ケース時点（FINDINGS.md）と同じ傾向がそのまま
50件まで安定して続いている: 「相手の計画を批評してください」と
明示的に頼まれた場面では、モデルは既に本の教えの大部分を自力で
再現できる。ズレが見つかるのは概ね1〜2割で、狙って再現する方法は
今のところ見つかっていない(設問形式仮説・reframe要求仮説・具体/
抽象バイアス仮説の3つを試して、いずれも安定した予測力を持たな
かった)。

確認された4つの原則（001〜004）はいずれも「相手が置いた前提

これが50件を通して唯一安定して見つかった、実務上再現性のある
盲点である。詳細は `FINDINGS.md` を参照。
