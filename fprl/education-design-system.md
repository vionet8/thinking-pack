## FPRL理論：基本構造

```
F（設計図）→ Pを起動する
P（観察）  → 差分をRに渡す
R（推論）  → 手順をLに渡す
L（学習）  → Fを更新する（完全ループ）
```

> 「Fとは、違和感を生み出すための設計図である」

---

## F（Foundation）完全分解

FはP・R・Lと違い、**始点かつ終点**である。
他の要素はFなしに機能しない。

### ① Fの手順（どう作るか）

**収集 → 抽出 → 定義 → 運用**

| ステップ | 内容 | 具体例 |
|--------|------|--------|
| 収集 | 良い/悪い事例を集める | 上手い人のやり方・自分の成功/失敗 |
| 抽出 | 共通点・差分を抜く | 何が効いている？何がダメだった？ |
| 定義 | 基準として固定する（最重要） | 「○○のときは△△する」シンプルなルール化 |
| 運用 | 実際に判断基準として使う | Pで照合される |

### ② Fの質（良いFとは何か）

> 良いF＝ズレを正しく検出できる基準

| 条件 | 定義 | 悪い例 | 良い例 |
|------|------|--------|--------|
| 明確性 | 曖昧じゃない | 「丁寧に」 | 「3回確認する」 |
| 判別性 | OK/NGが分かれる | 「いい感じに」 | 「〇〇があればOK」 |
| 再現性 | 誰でも使える | 属人的なカン | 手順として言語化されている |
| 有効性 | 成果につながる | 形式だけ正しい | 実際の差分検知に機能する |

### ③ Fの拡張（どう強くなるか）

**更新 → 精緻化 → 統合 → 転移**

| ステップ | 内容 |
|--------|------|
| 更新 | Lの結果を反映。成功/失敗を取り込む |
| 精緻化 | 粗いFを細かくする。条件・分岐を追加 |
| 統合 | バラバラのFをまとめる。上位ルール化・原則化 |
| 転移 | 他領域へ広げる。似た構造へ適用 |

**Fの進化イメージ**

```
経験
 ↓
F（粗いルール）
 ↓
更新・精緻化
 ↓
強いF（高精度基準）
 ↓
他領域へ転用
```

## P・R・L 完全分解

### P（Perception／観察）

**プロセス：検出 → 焦点化 → 比較**

| プロセス | 内容 |
|--------|------|
| 検出 | 差分の存在に気づく |
| 焦点化 | どこを見るかを絞る |
| 比較 | Fと照合してズレを測る |

**性質：感度・解像度・選択性**

> 重要：この段階では意味づけをしない。観察と解釈を混ぜると差分の精度が下がる。

### R（Reasoning／推論）

**プロセス：解釈 → 分解 → 手順化**

| プロセス | 内容 |
|--------|------|
| 解釈 | 差分に理由を与える |
| 分解 | 要素・順序・関係に分ける |
| 手順化 | 構造を実行可能な動作へ落とす |

**性質：抽象化・圧縮・転用**

> 「分かる」と「できる」の差は手順化まで完了しているかどうか。

### L（Learning／学習）

**プロセス：実行 → フィードバック → 更新**

| プロセス | 内容 |
|--------|------|
| 実行 | 手順化された動作を試す |
| フィードバック | 結果とFを照合する |
| 更新 | Fを修正・強化する |

**性質：再現性・安定性・適応性**

> Lの回転数が成長速度を直接決める。

## できる人とできない人の差

| 要素 | できる人 | できない人 |
|------|---------|-----------|
| F | ゴールのイメージが鮮明・基準が明確 | ゴールが曖昧・基準がブレる |
| P | 重要な差分を拾える・観察と解釈を分けられる | 差分が見えない・観察しながら解釈してしまう |
| R | 差分を再現可能な形に変換できる | 気づいても構造化できない・変換で止まる |
| L | 修正サイクルが速い | 試行回数が少ない・修正が遅い |

# 2タイプの比較

| | タイプA（変容型） | タイプB（積み上げ型） |
|---|---|---|
| 目的 | 前提の変容 | スキルの習得 |
| 設計起点 | ジンテーゼ（持ち帰り） | ゴールスキルの分解 |
| Fの役割 | 揺らす対象（テーゼ） | 最初に正しく作る |
| 気づきの数 | 1〜2個 | スキル数だけある |
| 失敗の役割 | 前提を揺らすため | 定着させるため |
| FPRLの使い方 | 全体構造 | 各スキルに適用 |
| 例 | 思考法・前提変容系の講義 | スクリプト言語・新人教育 |

## タイプの判断基準

迷わない。ターゲットと目的が先に確定している設計なので、分類は「選択」ではなく「ラベル付け」。

| 問い | 答え |
|------|------|
| ターゲットはすでに何らかのやり方・信念を持っているか？ | → タイプA（変容型） |
| ターゲットはまだそのスキル自体を持っていないか？ | → タイプB（積み上げ型） |

# 失敗設計（共通）

> 教材の質＝失敗設計で9割決まる

## 失敗の種類（タイプ別対応）

| パターン | 定義 | 対応タイプ | 崩し方 |
|--------|------|-----------|--------|
| 知識不足型 | 単純に知らない | B向け | 教えれば解決 |
| 誤解型 | 間違った理解をしている | B→Aの橋渡し | 比較で崩す |
| 信念型 | 正しいと確信している | A向け | 体験でしか崩れない |

## 失敗強度設計

> 「壊さずに揺らせ」

失敗は強ければいいわけではない。目的はFを壊すことではなく「揺らすこと」。

| レベル | 状態 | 学習者の反応 | 用途 | 注意 |
|-------|------|-----------|------|------|
| Lv1：違和感 | 「あれ？なんか違う」 | 自尊心へのダメージなし | Pを動かす。初回は必ずここ | 安全 |
| Lv2：ズレ自覚 | 「思ってたのと違う」 | 軽い否定・修正可能 | Rを動かす。標準的な設計 | 標準 |
| Lv3：前提崩壊 | 「今までのやり方ダメじゃん」 | 強い不快感・防御反応の可能性 | Aタイプの変容で限定使用 | フォロー必須 |
| Lv4：自己否定 | 「自分はダメだ」 | 自信喪失・学習停止 | **使用禁止** | NG |

### 失敗強度の設計ルール

1. 最初は必ずLv1から入る
2. 1回の指導で上げるのは1段階まで
3. Lv3はフォロー設計が必須
4. 失敗後に必ず成功体験を入れる

### 失敗設計の判断基準

この失敗は：

- 差分が明確か？
- 学習者が再現できるか？
- 防御反応が強すぎないか？
