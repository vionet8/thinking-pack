# 案件の取扱説明書（C）と見積もりの補正（D）から始める具体案

聞き取りで貯めた情報の使い道（`ai-interviewer.md` の「貯めた情報の使い道」）のうち、
検索の仕組みがなくても文書だけで始められ、次の案件の立ち上げですぐ効果が見える C と D から始める。

## 何のために、誰に、いつ、何を材料に

| | C. 案件の取扱説明書 ＋ 顧客への確認項目 | D. 見積もりの補正 ＋ 請求できる作業の見直し |
|---|---|---|
| ターゲット | 走り出しの時期の問い合わせ・待ち・手戻りで取られる、請求できない時間（分母） | 請求できずに吸収している作業（分子に入れられるもの） |
| 使う人 | 案件に入る人、案件リーダー | 案件リーダー、見積もりを出す人・営業 |
| 使う瞬間 | 配属の初日、顧客との立ち上げ会議の前 | 見積もり・契約のとき、仕様が変わったとき |
| 材料 | 終わった走り出し案件の聞き取り（場面6・8・9）、走り出し時期のチャット | 終わった案件の見積もり工数と実績工数（作業ごと）、案件リーダーの聞き取り（場面8） |
| 効く目標 | 問い合わせ減、ベテラン頼み減、ミス減 | 請求係数 |

C と D は同じ材料（終わった走り出し案件）から作れる。案件リーダーへの聞き取り（場面8）1回で両方の材料がとれる。

## 進め方（6週間）

調査→ターゲット決め→原因→対策検討→実施検証→結果比較 の流れに合わせる。

| 週 | やること | 担当 | できるもの |
|---|---|---|---|
| 1 | **調査**: 終わった走り出し案件を2〜3件選ぶ。作業ごとの見積もり工数・実績工数と、走り出し4週間のチャットを集める。チャットの問い合わせをAIで数える（下の指示文1） | AI調査チーム | 今の数字（基準値）: 問い合わせの件数・待ち時間、見積もりとのずれ |
| 1 | **ターゲット決め**: 次に始まる案件から試す案件を1〜2件決める。測るものと、比べ方を決める | AI戦略チーム | 試す案件、測るもの |
| 2 | 選んだ案件のリーダーに場面8、移ってきた人に場面6、離れた人がいれば場面9の聞き取り | 資産化チーム | 聞き取りの記録 |
| 2〜3 | **原因**: ずれと吸収作業を分類する（下の指示文2） | AI調査チーム | ずれの分類表 |
| 3 | **対策検討**: 取扱説明書・確認項目の下書き（下の指示文3）。見積もりの補正案と、請求の扱いの案 | 資産化チーム（C）、AI戦略チーム（D、見積もり・契約の担当と合意） | 取扱説明書、確認項目、補正案 |
| 4〜 | **実施検証**: 試す案件の立ち上げで使う。初日に取扱説明書を渡し、立ち上げ会議で確認項目を使う。見積もりに補正を入れる | 案件リーダー（資産化チームが付き添う） | 使った記録 |
| 4〜8 | 走り出し4週間の問い合わせを、週1回数える（指示文1） | AI調査チーム | 途中の数字 |
| 終わり | **結果比較**: 基準値と比べる。使われなかった項目、足りなかった項目を洗い出して取扱説明書を直す | 全員 | 次の版 |

## C. 案件の取扱説明書（1〜2ページ）のひな形

```
案件名 / 作成日 / 作成者 / 最後に直した日
1. この案件の目的: 顧客は何を決めるためにこの解析を使うか。合否の基準は何か
2. 前提と決まりごと: 単位系、座標系、材料物性・荷重・境界条件の出どころ、形状データの版、精度の要求
3. 置き場所と名前のつけ方: データ・モデル・結果・報告書の置き場所と命名のルール
4. 過去の経緯と例外: これまでに決まったこと、顧客の好み、例外的な対応
5. 誰に何を聞くか: 判断の種類ごとの相談相手（顧客側の窓口も）
6. よくある詰まり（上位5つ）: 症状 / 最初に確かめること / 分からなければ誰に聞くか
7. 最初の1週間でやること
8. まだ分かっていないこと（聞き取りで分からなかった点）
```

## C. 立ち上げ時に顧客へ確認する項目（叩き台）

以下は一般的な項目を並べた叩き台。場面8の「後から出てきて手戻りになった前提」で入れ替え、
実際に手戻りを生んだ項目を上に置く。

```
- 解析の目的と、結果で何を決めるか。合否の基準
- 形状データの版と形式。今後の変更の予定
- 材料物性・荷重・境界条件の出どころと確かさ（仮の値か、確定値か）
- 単位系・座標系
- 精度・メッシュ・計算時間の要求
- 報告書の形式と、中間報告の時期
- 前提が変わったときの扱い（追加の見積もりにするか、範囲内とするか）と、その判断をする人
- 質問の窓口と、回答までの目安
```

## D. 見積もりとのずれの記録表

```
作業の種類 / 見積もり工数 / 実績工数 / 差 / 差の理由 / 分類 / 次の見積もりへの反映
```

差の理由と分類:

| 差の理由 | 分類 | 手当て |
|---|---|---|
| 後から出てきた前提・仕様の変更 | 変更として請求できたはず | 確認項目（C）に入れる。契約に「前提が変わったときの扱い」を書く |
| 顧客からの回答待ち・データ待ち | 見積もりに入れるべき | 見積もりの補正。回答期限を立ち上げで決める |
| 範囲外の依頼を引き受けた | 請求できたはず | 追加見積もりの出し方を決める |
| 社内の問い合わせ・探し物・手戻り | 自社で減らすもの（請求はしない） | 取扱説明書（C）、確認リスト（B）で減らす |
| 作業の種類そのものの見積もりが甘い | 見積もりに入れるべき | 作業の種類ごとの補正係数（実績 ÷ 見積もり）を使う |

請求を増やす話は顧客との関係に関わるので、分類の結果を見積もり・契約の担当に渡して決めてもらう。
改善チームが決めるのは「どの作業に、どんな理由で、どれだけ吸収しているか」の事実まで。

## 測るもの（基準値と比べる）

| 使い道 | 測るもの | どこから |
|---|---|---|
| C | 走り出し4週間の問い合わせの件数と待ち時間（1人あたり） | チャット（指示文1） |
| C | 後から出てきた前提の件数 | 案件リーダーへの聞き取り（場面8） |
| C | 取扱説明書を見た回数と、見て解決した件数 | 使った人への短い聞き取り |
| D | 作業の種類ごとの、見積もりとのずれ（%） | 工数の記録 |
| D | 吸収した工数、請求係数 | 工数の記録 |

## 指示文1: チャットの問い合わせを数える（基準値と途中の数字）

```
次は、ある案件の走り出し時期のチャットです。問い合わせ・確認を数えて表にしてください。
1. 1件ごとに: 日時 / 質問した人の立場（新人・移ってきた人・中堅・その他） / 質問の種類（前提・置き場所・手順・判断・顧客への確認・その他） /
   作業の種類 / 最初の質問文（引用） / 回答までの時間 / 答えた人
2. 質問の種類ごと、作業の種類ごとの件数と、回答までの時間の合計
3. 取扱説明書や資料があれば聞かずに済んだと思われるものに印をつけ、理由を1行で書く
材料にないことは書かない。判断できないものは「不明」とする。
```

## 指示文2: ずれと吸収作業を分類する

```
次は、終わった案件の作業ごとの見積もり工数・実績工数と、案件リーダーへの聞き取りの記録です。
1. 作業ごとに、差（実績−見積もり）と比（実績÷見積もり）を計算する。数字は材料のまま使い、作らない。
2. 差が大きい順に、聞き取りの記録から差の理由を引用する。理由が記録にないものは「理由不明（次に聞く）」とする。
3. 差の理由を、表の分類（変更として請求できたはず／見積もりに入れるべき／請求できたはず／自社で減らすもの）に分ける。
4. 分類ごとの工数の合計と、作業の種類ごとの補正係数を出す。
5. 次の聞き取りで確かめたいことを3つ挙げる。
```

## 指示文3: 取扱説明書と確認項目の下書き

```
次は、ある案件の聞き取りの記録（案件リーダー・移ってきた人・離れた人）と、走り出し時期のチャットの集計です。
上の「案件の取扱説明書」のひな形に沿って下書きを作ってください。
- 各項目の終わりに、根拠にした記録（誰の聞き取りの何問目、どのチャット）を書く。
- 記録にないことは書かず、「8. まだ分かっていないこと」に入れる。
- 「6. よくある詰まり」は、チャットの集計で件数が多い順に、質問した人の言葉で症状を書く。
- 「後から出てきて手戻りになった前提」は、顧客への確認項目の案として別に並べる。
```

## 間違っているとしたら、ここ

- **作業ごとの見積もり工数・実績工数が記録されていない**と、D は始められない。その場合は、
  場面8の聞き取りで作業ごとの「膨らんだ・吸収した工数の目安」を聞き、概算で始める。
- **取扱説明書を作っても読まれない**おそれがある。初日に案件リーダーが一緒に読む時間を15分とる、
  を実施の手順に入れる。読まれたかは「測るもの」で確かめる。
- 試す案件が1〜2件だと、良くなっても案件の違いのせいかもしれない。結果比較では、
  数字と合わせて「取扱説明書のどの項目で聞かずに済んだか」を具体的な件で集める。
