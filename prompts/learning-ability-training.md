# 学習能力を鍛える手法（学び方を学ぶ）

「投資すべき5つの知的能力」の1位（学習能力＝新しい知識や技術を効率よく身につけ、使えるところまで持っていく力）を、
実際に鍛えるための手順。FPRLとの対応（`sources/research/fprl-and-five-abilities.md`）の結論「Fの量でやり方が切り替わる」を軸にした。

## 何のために、誰に、いつ、何を材料に

- **ターゲット**: 学んだことが「時間が経っても」「初めての場面でも」使える割合を上げる（FPRLでいえば、内部Fへの定着と転移）。
  学ぶ量を増やすのではなく、同じ時間で残る量を増やす。
- **誰に**: まず本人。同じ形で新人・チームにも使える（下の「新人・チームに使うとき」）。
- **いつ**: 何か新しいことを学ぶとき。例（これに限らない）: 動画・本、新しい道具（AIなど）、仕事の新しい種類の作業、資格の勉強。
- **材料**: いま学んでいる中身そのもの。学習能力だけを別に練習しない。学び方の訓練は、実際に学ぶ中身の中でやらないと、
  ほかの場面に移りにくい（遠い転移は起きにくい、という研究と同じ理由）。
- **測るもの**: ①1週間後に見ずに思い出せた割合　②思い出せる数の予想と実際のずれ　③学んだことで次の一手が変わった数。

## 考え方（3つ）

1. **段階でやり方を変える。** 手本から学ぶのが良い段階と、自分で試して失敗する方が良い段階がある。切り替えるのはFの量
   （その分野の土台がどれだけあるか）と、正誤がすぐ分かるかどうか。
2. **読み直さず、思い出す。間を空けて、もう一度思い出す。** 読み直し・要約・線引きは、その場の「分かった感」は強いが残りにくい。
3. **外れを材料にする。** 予想してから答え合わせする。試して通用しなかった所を見つけて、やり方を変える。

## 1. 段階を見立てて、やり方を選ぶ

見立ての問いは2つ。「手本を見ずに、最初の一歩を書けるか（やれるか）」「やった結果の正誤は、すぐ分かるか」。

| 今の状態 | やり方 | なぜ |
|---|---|---|
| 手本を見ずに最初の一歩が書けない（Fがほぼない） | 手本で学ぶ。手本は2つ以上を並べて、共通する所と違う所を書き出す | 失敗が「大きすぎる差分」になり、処理できない。2つ比べると、表面ではなく構造が取り出せる |
| 最初の一歩は書ける ＋ 正誤がすぐ分かる | 先に自分で試す。わざと難しめの例に挑んで失敗し、何が通用しなかったかを確かめて直す（エラーマネジメント） | 初めて見る問題への応用で、手本から入るより良い結果が出ている |
| 最初の一歩は書ける ＋ 正誤が後まで分からない | 正しいやり方を先に見てから試す。試した後に必ず答え合わせの場を作る | 答え合わせのない失敗は、間違ったやり方の方を定着させることがある |
| 手本なしでおおむねできる | 手本を使わない。条件を変える、種類の違う問題を混ぜて練習する、「なんか違う」という小さな違和感を探す | 手本は小さすぎる差分になり、学びにならない（熟達化反転）。ここからは境界の違和感がFを鋭くする |

段階は分野ごと・作業ごとに違う。同じ人でも、ある作業では1行目、別の作業では4行目になる。

## 2. 毎回の型（1つの学びにつき合計5分ほど）

| いつ | やること |
|---|---|
| 学んだ直後 | 閉じて、見ずに要点を3つ書く（音声入力でよい）。元と比べて、抜けたものに印をつける |
| 2〜3日後 | 先に「いくつ言えそうか」を予想する → 見ずに書く → 答え合わせ → 予想とのずれを1行残す |
| 1週間後 | 同じことをする。加えて「これで次の一手が変わったか」を1行 |
| 1か月後 | 抜けやすかったものだけ、もう一度 |

- 予想と答え合わせは、自分の出来を見誤るクセ（メタ認知）の訓練も兼ねる。どんな題材で高く・低く見積もるかが見えてくる。
- 「次の一手が変わったか」は、FPRLの定着の目印（その学びを前提にした次の一手が変わったか）と同じ。

## 3. 失敗ノート（試す作業があるとき）

```
試したこと：
通用しなかった所（事実）：
たぶんの原因：
次に変えること（1つ）：
別の場面で試した結果：
```

- 効く要素は2つ。自分で探ること、そして「失敗は材料」と先に決めておくこと。
- やる場所は、正誤がすぐ分かり、失敗しても困らない所に限る（練習用のデータ、過去の題材、小さい範囲）。

## 4. 進む基準を先に決める（自分を管理する）

始める前に、次の4つを1行ずつ決める。

- いつ手本を使うか
- いつ自力でやるか
- どこで答え合わせをするか
- 何ができたら次の段階に進むか（例: 手本なしで最初の一歩が3回続けて書けたら、表の2行目へ）

## 今の仕組みに埋め込む（最初の4週間の試し）

本人はいま、動画や本の要約を thinking-pack に送って貯めている。要約は貯めて検索するためには良いが、
本人が覚えるための手段としては弱い（要約・読み直しは、学習法の大規模なレビューで効果が低い評価）。そこで一手だけ足す。

1. **送る前に、見ずに要点を3つ書いて一緒に送る。** Claudeは要約と比べて、抜けたものを返す。書いていなければ、要約を受け取った後に一言だけ促す（強制しない）。
2. **Claudeは確認の日を、ハンドアウトの「思い出し待ち」に載せる。** 次のチャットの最初に、期日が来たものを1問だけ出す
   （先に「いくつ言えそうか」予想 → 見ずに答える → 答え合わせ）。
3. **最初の週は基準を取る。** 練習していない過去の動画で、今どれだけ思い出せるかを測る（例: 9/29の樺沢氏『知性大全』、AIエージェントの7つの要点）。
4. **4週間後に、3つの指標を基準と見比べる。** 思い出せる割合が基準より上がらない、または手間で続かないなら、やめるか型を減らす。

## 新人・チームに使うとき

- 新人向けタイプBシート（`prompts/newcomer-typeB-sheet.md`）のスキルごとに、段階の表を当てる。
  例（これに限らない）: 検算（S1）は正誤がすぐ分かるので、最初の一歩が書けるようになったら失敗から学べる。前提の確認（S2）は誤りが後まで分からないので、手本を先に見せる。
- 教える側は「今どの段階か」で手本の量を変える。同じ教え方を続けると、上達した人には逆に効かなくなる。
- 仮説カード（`prompts/hypothesis-card.md`）の「当たり外れの見分け方を先に決める」は、予想→答え合わせと同じ型。

## 向かない場面

- 見た目や手の感覚を育てている途中の人に、その場で言葉にさせすぎること（言葉にすると、かえって見る力が落ちることがある）。
  その場では印をつけるだけにして、言葉にするのは後で。
- 疲れているとき・睡眠不足のとき。型を回すより休む方が先（『覚醒の科学』の要約）。
- 失敗すると危ない、取り返しがつかない作業での「失敗から学ぶ」。

## 間違っているとしたら、ここ

- 学習能力そのものが分野をまたいで伸びるかは、研究ではまだ弱い。この手法は「学んでいる中身ごとに効く」前提で作り、測るのも中身ごと。
- 手間が増えると止まる。最初は「直後に3つ書く」と「1週間後に1問」だけでよい。
- 比べる相手がいない1人の試しなので、題材の難しさの違いが結果に混ざる。

## 根拠

| 研究 | 内容 | 状態 |
|---|---|---|
| Dunlosky ら（2013, Psychological Science in the Public Interest） | 10の学習法を評価。思い出す練習（小テスト）と間隔を空けた練習が最も高い評価。要約・線引き・読み直しは低い評価 | 検索で確認 |
| Keith & Frese（2008, Journal of Applied Psychology） | エラーマネジメント訓練のメタ分析（24研究・2183人）。全体で d=0.44、訓練と構造が違う課題への転移で d=0.80。効く要素は自分で探ることと失敗を勧めること | 検索で確認 |
| 頭部CT読影のエラーマネジメント訓練（救急科研修医のランダム化比較試験） | 失敗して学んだ群が、初めて見る症例で誤りが少なかった | 検索で確認（`sources/videos/misc-videos.md`） |
| Roediger & Karpicke（2006） | 読み直しは5分後に強く、思い出す練習は2日後・1週間後に強い。読み直した人ほど自信が強い | 推定（動画の内容と一致） |
| Kalyuga ら（熟達化反転） | 初心者には解答例、経験を積んだ人には自力の問題解決が効く | 私の知識から |
| Gentner ら（類推による符号化） | 2つの事例を比べて共通の構造を取り出すと、転移が増える | 私の知識から（`sources/research/fprl-counterexamples.md`） |
| Baddeley & Wilson（1994） | 答え合わせのない誤りは、誤りの方を強めることがある（誤りなし学習） | `sources/research/fprl-counterexamples.md` |
| Schooler（言語隠蔽） | 知覚の力が言葉の力を上回る段階では、言葉にさせると判断が落ちる | `sources/research/fprl-counterexamples.md` |
